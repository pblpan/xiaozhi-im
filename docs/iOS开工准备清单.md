# iOS 版开工准备清单

> 现状：**Mac 和 Apple 开发者账号都还没有，所以还不能出 iOS 安装包。**
> 但苹果端**唯一不依赖 Mac 的那一半（服务端推送）已经做完并实测过了** —— 见文末。
> 这份清单是给"东西到齐之前"用的：要先办什么、怎么办、多少钱、多久，以及东西齐了当天我做什么。
>
> 最后更新：2026-09-16

---

## 一、三个卡点

| # | 卡点 | 大概成本 | 到手时间 | 没有它行不行 |
|---|---|---|---|---|
| 1 | **Apple 开发者账号** | ¥688 / 年 | 1–3 天（含实名审核） | **不行**。没有它，App 装不到 iPhone 上（免费账号只能自己用 7 天，且不能推送） |
| 2 | **一台 Mac** | 二手 Mac mini ¥2500 起，或按天租云 Mac | 当天（买/租） | **不行**。苹果只允许在 macOS + Xcode 上编译 iOS 应用 |
| 3 | **一台真机 iPhone + 一个 .p8 推送密钥** | iPhone 用现有的；.p8 随账号免费生成 | 账号到手当天 | 打包能在模拟器上跑，但**推送必须真机**（模拟器收不到 APNs） |

**这三样是串行依赖**：先办账号（等审核），同时准备 Mac，账号下来后立刻生成 .p8、注册设备。

## 二、卡点 1：Apple 开发者账号怎么弄

### 办哪个

| 类型 | 费用 | 适不适合我们 |
|---|---|---|
| **个人 (Individual)** | ¥688 / 年 | ✅ **选这个**。内部自用完全够，不需要公司资质、不需要邓白氏编码 |
| 公司 (Organization) | ¥688 / 年 | ❌ 要多一个 D-U-N-S 编码，审核 1–2 周，只为让 App Store 上显示公司名 |
| 企业 (Enterprise) | ¥1998 / 年 | ❌ 需要 100 名以上员工 + 严格审核，我们不是这个场景 |

### 要准备什么

1. 一个 **Apple ID**（普通 Apple ID 就行，但**必须开启双重认证**，否则注册页会卡住）
2. **本人身份证**（个人账号要实名，姓名要与身份证一致）
3. 一个能付款的方式（信用卡 / 部分渠道支持国内支付，以 apple.com 官网结算页为准）
4. 手机号（收验证码）

### 在哪办

`developer.apple.com` → Account → 用 Apple ID 登录 → Enroll（加入开发者计划）。

注册后**立刻会验证身份**（个人账号通常是填姓名地址 + 身份证信息，部分情况要求上传证件）。审核一般 **1–3 个工作日**，通过后邮箱会收到确认。

> ⚠️ 一个容易踩的坑：注册时填的**姓名**会出现在 App 的版权信息和设备管理里。用真名即可，别填公司名（个人账号填公司名会被要求转公司账号，重新审核一遍）。

### 账号到手后，App 怎么发给员工用

这是内部系统，**不上 App Store**。三条路：

| 方式 | 上限 | 麻烦点 | 建议 |
|---|---|---|---|
| **TestFlight**（内测） | 10000 人 | 每个版本**90 天过期**，到期要重新发一次 | ✅ **推荐**。员工点个邀请链接就装上，不用报手机号 |
| **Ad Hoc**（指定设备） | 100 台 / 年 | 要**收集每台 iPhone 的 UDID**，加一台设备就要重新打包 | 设备固定、且不想每 90 天重发时用 |
| 企业证书自签分发 | — | **违规**，证书随时被吊销，所有手机上的 App 一起变砖 | ❌ 别用 |

> 我们的场景（工厂 / 门店十几到几十台）建议先用 **TestFlight**：省事，缺点是每 90 天要重发一次包 —— 这个到时候可以做成定时任务提醒。

## 三、卡点 2：Mac 怎么解决

编译 iOS 必须用 Xcode，而 Xcode 只跑在 macOS 上。三种办法：

| 方案 | 大概花费 | 说明 |
|---|---|---|
| **二手 Mac mini（M1/M2）** | ¥2500–4000 | ✅ **最划算**。买回来放办公室，长期能用，编译速度够快 |
| 二手 MacBook Air M1 | ¥3000–4500 | 顺便能当笔记本用 |
| 苹果官翻 / 全新 Mac mini M4 | ¥4000+ | 预算够就上新 |
| **租云 Mac** | ¥30–100 / 天，或月租 | 只适合"先试一次"，长期做维护不方便（传包麻烦、Xcode 版本不可控） |

**最低要求**：Apple 芯片（M1 及以上）+ **16 GB 内存** + 256 GB 硬盘。
Intel 的旧 Mac 也能编，但 Xcode 新版本已经不支持，会卡在系统版本上 —— 别买。

> 顺带：Flutter 项目在 Mac 上编译 iOS 的体验比 Android 好，一次配好之后每次出包就是一条命令。

## 四、卡点 3：账号 + Mac 到位当天要做的三件事

这三件事做完，我就能开始出第一个能装的测试包（大约 1 天）：

1. **注册 App ID**
   Bundle ID 已经定好了，**必须一字不差**（改了推送就失效）：
   ```
   com.pblpa.xiaozhiIm
   ```
   在 developer.apple.com → Identifiers → 新建 App ID → 勾选 **Push Notifications** 能力。

2. **生成 .p8 推送密钥**
   Keys → 新建 Key → 勾选 **Apple Push Notifications service (APNs)** → 下载 `.p8`。
   ⚠️ **这个文件只能下载一次**，丢了只能删掉重新生成一个（旧的立刻失效）。
   同时记下两个值：**Key ID**（10 位）和 **Team ID**（10 位）。
   → 这三个值（.p8 / Key ID / Team ID）填进管理台或接口，服务端推送就能用了（**服务端那部分我已经写好测好了**）。

3. **注册测试设备**
   告诉我要用哪几台 iPhone 做测试（TestFlight 的话不用登记 UDID，发邀请即可；Ad Hoc 需要每台的 UDID）。

然后我这边按 `docs/iOS推送方案-APNs.md` 里的 **D1 八步**往下走：装 Xcode → `pod install` → 接推送（原生侧代码我已经写好了骨架）→ 真机跑通 → 出测试包。

## 五、已经做完的部分（不需要 Mac 也能做的都做了）

### 服务端推送（最关键的一块，已完成并实测）

iOS 和 Android 最大的差别在**后台**：安卓端可以靠长连接 + 保活，iOS 不行 —— 应用切后台后长连接很快被系统掐掉，**必须走苹果的 APNs 推送**，否则用户锁屏后收不到任何消息提醒。

这一层是纯服务端的活，已经做完了：

- 用 Apple 官方 `.p8` 方式签 JWT（**零新增依赖**，只用 Node 自带的 crypto），只走出站 443 端口，**不需要任何路由器端口映射**
- **在线不推**（消息已经实时到了，再推一次是打扰）、**自己发的不推**
- 单聊标题取「对方视角的会话名」（含你给对方的备注），群消息标题是群名、正文带发送者
- 各类型只给一句话预览（锁屏上不该摊开私聊正文）
- **只有令牌真的失效（410）才作废设备**；苹果侧 5xx 抖动绝不把设备下线 —— 这个判错就是"用户再也收不到推送"
- 同一台手机换人登录，**旧账号的推送立刻停**（否则新用户会收到上一任用户的私聊提醒）

**实测：本机用假 APNs 跑通 80 项断言全过**，JWT 是拿公钥**真验签**的。
反向验证也做了：把签名算法的一个参数拿掉后，恰好那条验签断言失败 —— 证明判据不是摆设（这个参数写错，苹果只会回一个 `403`，什么都看不出来）。

### 客户端侧代码准备（不需要 Mac 的部分）

- iOS 工程生成脚本（无 Mac 也能在 Windows 上生成/刷新工程文件）
- **ATS 网络策略**：改用 `NSAllowsLocalNetworking`，覆盖内网 IP / `.local` / 无后缀主机名，**不再把任何服务器地址写进工程文件**
- 版本号与 Android / Windows 三端同步（当前 0.14.0）
- 静态核验 **40/40 通过**

### iOS 上会与安卓不同的地方（提前知道，避免期望错位）

| 功能 | iOS 上的情况 |
|---|---|
| 消息推送 | 走 APNs（已就绪），后台能收到 |
| 音视频通话 | WebRTC 支持，但**后台/锁屏来电**要比安卓多做一步（VoIP 推送 + CallKit），本期先不做，锁屏来电会退化成一条普通通知 |
| 被远程控制 | ❌ 苹果沙箱不允许，和安卓一样只支持"看屏幕"
| 分享到小智 | 走 iOS 的 Share Extension，能做，但要在 Xcode 里加一个扩展 target |
| 最低系统版本 | iOS 15.0（已定） |

> 对象：`base.apk` = `com.byt.pgshop`（比优特商业集团零售 App，v1.0.94 / versionCode 94，原生 Android，R8 混淆，5 dex，minSdk 26）
> 目的：把它的能力"学过来"落到小智 IM，并把小智的能力做成开放接口
> 日期：2026-09-19

## 0. 先说一个必须纠正的事：上一版勘测报告有假阴性

写这份方案前，我用同一套脚本复核了上一版报告的结论，发现**报告里一批"0 命中/未找到"是错的**。根因不在数据，在我自己的解析器：

- `arsc_strings()` 解析 UTF-8 串时**只读了串头的第一个长度**（UTF-16 码元数），就拿它去切字节。
  AOSP 的 UTF-8 串头其实有**两个** varint：`[码元数][字节数][数据]`。
- 纯 ASCII 下字符数 == 字节数，看不出问题；**一遇中文（3 字节/字）必然截断**，还把第二个长度字节混进串首。
- 变异测试里的旧逻辑输出直接暴露病灶：`'\x0c库'`、`'\x0c抽'`、`'\x18扫描?'` —— `\x0c`=12 正是"库位管理"的**字节长度**被当成字符长度。
- 影响：唯一串 3146（截断）→ 修复后 3867（完整），全表乱码串归零。

**被冤枉的结论（实测均存在，报告写成"未找到"）**：

| 报告说法 | 实测 |
|---|---|
| `libscannative.so` 0 命中、未找到 | ✅ 存在：`lib/arm64-v8a/libscannative.so`、`lib/armeabi-v7a/libscannative.so` |
| `assets/detect.ms` 无此文件 | ✅ 存在：`assets/detect.ms`(679KB)、`assets/angle.ms`、`assets/corner.ms` |
| `库位管理`/`抽盘完毕` 等中文串 0 命中 | ✅ 存在（在 **DEX 字符串常量**里，不在 ARSC） |

**两条要记住的经验**：
1. 「0 命中」不等于「不存在」——**先怀疑提取器**，别先怀疑事实。否则整份报告的结论都被带偏。
2. 这个 App 的中文 UI 文案主要活在 **DEX 字符串常量**（24 万条），不在 `resources.arsc`（仅 3867 条）。
   只查 ARSC 会漏掉绝大部分业务词。已固化为回归测试 `test_arsc_strings.py`（合成样本 + 真机样本 + 反向断言 + 变异测试，全绿）。

## 1. 能不能直接对接？不能

它是比优特**自研 App + 自己的 ThinkPHP 后端**：

- 路由是 ThinkPHP 形态：`index.php/模块/控制器/方法`
- 域名均为比优特自有：`*.bytdev.com`（含 `pandian.bytdev.com`、`qyh.bytdev.com:40000`）、`*.butsd.com`、`*.butsdgc.com`、`*.chzhlh.com`
- 鉴权：`token` + **自签 `sign`**（全包 1209 处）+ `timestamp` / `nonce` / `client_secret`，另接阿里云 STS —— 服务端签名，密钥在它手里，第三方无法复算

结论：**"把它的功能做成开放接口融入我们系统"的正确读法是——复刻它的业务能力，再用我们自己的开放 API 暴露出去**（也就是 ② 要做的签名加固版开放接口）。不是去连它的接口。

顺带：应用台里还有 `assets/pick_up_goods.json`、`pick_up_platform.json`（拣货规则落成 JSON 下发），以及自研 native 扫码库（`libscannative.so` + 三个 `.ms` 检测资源）——这是它扫码体验好的原因，我们可以不跟。

## 3. ① 盘点系统复刻方案

### 3.0 名字与 id 的分配（先把地盘划清楚）

原有模块显示名「门店盘点」**已改名为「扫码枪」**（v0.14.7），把「盘点」这个名字让出来给 M1。
两者的边界：

| | 扫码枪（已有，v0.14.7） | 盘点（M1 新建） |
|---|---|---|
| 干什么 | 把条码快速扫成一笔账：扫码 → 明细 → 导出 → 盈亏表 | 盘点制度：盘点位 / 库位货架位 / 初盘-复盘-抽盘 |
| 显示名 | **扫码枪** | **盘点** |
| 模块 id | `stocktake`（**已发布，永不可改**） | `inventory`（新分配） |
| 图标 | `barcode` | `inventory` |
| 界面用词 | 一律"扫码 / 扫码单" | 一律"盘点 / 盘点位 / 盘点单" |
| 导出文件名 | `扫码_单号.csv`、`扫码明细_单号.csv/.txt` | `盘点_单号.*`（不冲突） |

⚠️ **id 与显示名故意不一致**（`stocktake` 显示成「扫码枪」）——因为 id 发布后改名等于
老客户端丢入口。以后看代码别拿 id 去猜标题。

⚠️ 服务端 `server/src/apps.js` 的 `title` 才是工作台显示的名字，客户端只是照着渲染。
改标题必须**同时发客户端 + 部署服务端**，只发一边会出现"图标叫 A、点进去叫 B"。

### P1 —— 盘点内核（对齐三遍制 + 盘点位 + 库位）

**本地库迁移到 v2**（`local_db.dart`，现有 `schemaVersion = 1`，按既有约定**只在迁移列表末尾追加，不动已有函数**）：

```sql
-- 盘点位
CREATE TABLE stocktake_zone (
  zone_code TEXT PRIMARY KEY, zone_name TEXT, store_code TEXT,
  locked INTEGER NOT NULL DEFAULT 0, created_at INTEGER);

-- 库位 / 货架位
CREATE TABLE location (
  loc_code TEXT PRIMARY KEY, loc_name TEXT, zone_code TEXT, sort_no INTEGER);

-- 商品 ↔ 货架位 绑定（一个商品可多货架位）
CREATE TABLE barcode_location (
  barcode TEXT, loc_code TEXT, bound_at INTEGER,
  PRIMARY KEY (barcode, loc_code));

-- 盘点单（一张单 = 一个盘点位 × 一个阶段）
CREATE TABLE stocktake_sheet (
  sheet_no TEXT PRIMARY KEY, zone_code TEXT,
  phase INTEGER NOT NULL DEFAULT 1,      -- 1初盘 2复盘 3抽盘
  status INTEGER NOT NULL DEFAULT 0,     -- 0进行中 1已提交 2已上传
  operator TEXT, started_at INTEGER, submitted_at INTEGER, uploaded_at INTEGER);

-- scan_record 加列（已存在，ALTER 追加）
ALTER TABLE scan_record ADD COLUMN phase  INTEGER NOT NULL DEFAULT 1;
ALTER TABLE scan_record ADD COLUMN loc_code TEXT;
```

**阶段流转规则**（这是复刻的核心，也是最容易做歪的地方）：

1. 扫盘点位码开单 → 若该点位有未完成单 → 弹"您在该盘点位有未完成数据，是否继续盘点？"
2. `phase=1` 初盘：全量扫，扫到的商品必须属于该点位，否则提示"当前盘点位不包含该商品"
3. 单点位条数达到上限（常量，默认 500）→ 拦截并提示"请提交后继续盘点！"
4. 提交 → 该点位锁定，生成差异集（`qty - account_qty != 0`）
5. `phase=2` 复盘：**只允许扫差异集内的商品**（对齐"2.复盘有差异数据"）
6. `phase=3` 抽盘：**必须持抽盘授权**（P2），扫完出"抽盘差异数据"
7. 上传 → `status=2`，`scan_record.uploaded=1`

**失误笔数**：某点位在 phase N 被扫过、又在 phase N+1 被改成不同数量的行数 = 该阶段失误笔数（对齐"初盘失误笔数/复盘失误笔数"）。

**交互补齐**：盘点位锁定 / 解除锁定 / 删除已锁定盘点位 / 清除缓存（二次确认，清点位+清数据两项）/ 切换盘点位前清空本地数据（二次确认）。

**服务端接口**：

```
POST   /api/stocktake/zone                  建/查盘点位
POST   /api/stocktake/sheet                 开单 {zone_code, phase}
GET    /api/stocktake/sheet/:no             单据详情（含差异集）
POST   /api/stocktake/sheet/:no/scan        批量上报扫描（幂等：sheet_no+barcode+phase 唯一）
POST   /api/stocktake/sheet/:no/submit      提交并锁定
POST   /api/stocktake/sheet/:no/upload      上传
GET    /api/location/by-barcode/:barcode    查商品货架位
POST   /api/location/bind                   绑定/解绑
```

**验收（真机）**：一个真实货架 → 扫点位码 → 扫库位码 → 扫 20 个商品 → 提交 → 故意改 3 个数复盘 → 抽盘改 1 个 → 看三阶段差异与失误笔数对不对；断网全程跑一遍再联网上传。

### P2 —— 权限与审批

- 角色：盘点员 / 盘点主管。抽盘授权落表 `stocktake_grant(user_id, zone_code, granted_by, granted_at, revoked_at)`
- **服务端强制校权**，不是前端隐藏按钮（PG 文案是"联系有权限的管理干部"，说明它是后端拦的）
- 通用审批中心：`POST /api/approval/submit`、`GET /api/approval/mine?status=`、`POST /api/approval/:id/approve|reject`（**驳回理由必填**）

### P3 —— 生鲜场景增值（可后置）

- 电子秤码解析：店内码前缀 + 商品码 + 重量/价格 + 校验位（生鲜盘点绕不开）
- 蓝牙价签打印：蓝牙标签机指令；**注意 PG 踩过的坑** —— 安卓 8.0+ 搜蓝牙必须打开 GPS 定位
- 库房减货 / 补货单：复用盘点单表结构，加 `sheet_type` 区分

## 4. ② 开放 API 签名加固

**现状**：只有长期有效的 Bearer token。一旦泄露 = 可无限重放，且无法定位是谁在调。

**加固设计**：

```
请求头：
  X-App-Id     应用标识
  X-Timestamp  unix 秒
  X-Nonce      随机串（一次一用）
  X-Sign       HMAC-SHA256(app_secret,
                 method + "\n" + path + "\n" + timestamp + "\n" + nonce
                 + "\n" + sha256_hex(body))
```

服务端校验顺序（任一不过即拒，且**先拒后办**）：

1. `X-App-Id` 存在且未禁用 → 否则 401
2. `|now - X-Timestamp| <= 300s` → 否则 401（防过期重放）
3. `nonce` 落表 `api_nonce(nonce PRIMARY KEY, app_id, at)`，唯一冲突 → 409（防同窗重放）
4. 重算签名，`hmac.compare_digest` 定时安全比较 → 否则 401
5. body 的 sha256 与签名一致 → 否则 401（防中途改包）

配套：`api_client(app_id, app_secret, name, enabled, created_at)`；密钥只存哈希？——**不，HMAC 需要原文**，所以 `app_secret` 加密存储（复用现有密钥），管理台支持**发密钥 / 停用 / 轮换**，日志记 `app_id` 便于溯源。

**回归测试必须包含反向断言**（否则就是装饰品）：
- 签名篡改 1 字节 → 401 ✅
- 时间戳改成 10 分钟前 → 401 ✅
- 同一 nonce 用两次 → 第二次 409 ✅
- 正确签名 → 200 ✅
- 变异测试：把时间窗判据改成恒真，测试必须报红

保留 `Bearer token` 给内部客户端（App 自身），开放接口走签名 —— 两条通道并存，不互相污染。

## 5. ③ 培训中心（名字就叫"培训中心"）

PG 那套"商学院"实测是一个完整的 LMS，不是放几个视频：

| 能力 | 它的证据串 |
|---|---|
| 课程库 | 公共课程 / 已加入我的课程 / 加入课程 |
| 付费/积分 | 付费课程 / 付费课程微信购买 / 付费课程纯积分购买 / 答题最多可获得积分 |
| 学习进度 | 学习课程退出时 / 申请学习 / 是否确认发起申请学习当前课程? / 已超过当前课程可学习时间 / 学习成长记录 |
| 考试 | 章节考试 / 开始考试 / 提交考试 / 答题卡 / 查看答题卡 / 当前课程进度未达标，暂不能参加考试 |
| 考试机会管控 | 是否确认退出考试？退出考试后将浪费本次考试机会。 |
| 年度培训 | 年度培训 / 年度培训进度 |
| 视频播放 | ijkplayer + soundtouch（**变速播放**，学习场景刚需） |

**我们的落法**（素材：`Y:\培训资料` 200+ 视频/课件）：

- 数据模型：`course / chapter / lesson(视频·文件) / enroll / progress / exam / question / option / answer_sheet / points_log`
- 视频：直接 mp4 + 服务端 **Range 支持**（NAS 弱，不做转码），播放器支持倍速
- 进度：`progress(user_id, lesson_id, position_sec, done, updated_at)`，退出即上报（对齐"学习课程退出时"）
- 考试：章节考试 → 答题卡 → 提交判分 → **一次机会**（对齐"浪费本次考试机会"）
- 门禁：课程进度未达标不放行考试
- 入口在客户端应用台写死名字 **"培训中心"**
- 积分体系（可选，最后做）：答题得积分

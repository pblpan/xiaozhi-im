# 简易盘点通道 方案 v1

> 龙哥 2026-09-25 提的：现有「盘点」是**制度型**（点位 / 货架位 / 三遍互比），
> 跟他在现场干活的方式背驰。他要的是**一条简易通道**：先导入这一轮要盘的明细，
> 再一趟一趟盘（节点），最后导出一张全量盘点数据单。
>
> 名字与 id：**「简易盘点」/ `simple_stocktake`**（服务端 0.21.2 已注册）。

---

## 0. 已确认的口径（龙哥定的，别自己改）

| # | 事项 | 结论 |
|---|---|---|
| 1 | 通道关系 | **独立通道**：不挂在「盘点」子目录下，不共用点位 / 货架位 / 商档设置。两套并存，现有「盘点」一行不动 |
| 2 | 待盘清单来源 | **手机上选 CSV 文件导入**（每一轮导一次） |
| 3 | 入口 | **单独一张工作台卡片**（不藏在别的页面里） |
| 4 | 一趟内同码多次扫 | **累加** ← 这就是"一个商品被两次盘到的累计" |
| 5 | 初盘数与复盘数**不一致** | 🔴 **该商品不导出**，进差异集 → 差异复盘再盘一次确认，**以差异复盘的数为准** |
| 6 | 差异复盘那一趟 | **只能扫差异集**：第 3 趟只显示前两趟对不上的，**对上的不再盘** |
| 7 | 扫到清单外的商品 | **不拦**，入账；导出时作**第三段**「未录入盘点计划商品」 |
| 8 | 没盘到的商品 | 也要出，数量 **0** |
| 9 | 导出形式 | **一个 CSV，三段**（各带自己的表头） |
| 10 | 场景标识 | 任务上要带：**仓库 / 卖场（门店）**。仓库也走一遍完整的初盘-复盘-差异复盘，与卖场分开 |
| 11 | 比优特的账面口径 | **不比账面**（门店没有可用的库存账；`v_realtime_stock` 3.4 万行全是 0）。差异只在**本次盘点的各趟之间**比 |

🔴 **第 5 条是最容易做歪的地方**：初盘 5 / 复盘 3 **不是 8、也不是 3** ——
是"这个商品两个人数的数不一致，还没定下来"。**导出必须把它排除掉**，
而不是替用户挑一个数。挑一个数就是在替盘点员签字。

### 「数量相加」到底加什么（避免以后有人照着"相加"做错）

- ✅ **加**：同一趟（同一节点）里，同一条码扫了多次 —— 货在货架上、仓库里各有一份，
  两次都算这个商品的同一张单里，**累加**。
- ❌ **不加**：初盘的数量 + 复盘的数量。那是**两个人对同一批货各数一遍**，
  两个数加起来等于把 5 件货算成 8 件。

## 1. 与「盘点」的分工

| | `inventory` 盘点（已有） | `simple_stocktake` 简易盘点（新） |
|---|---|---|
| 性质 | **制度型**：点位 / 货架位 / 三遍互比 / 失误笔数 | **干活型**：点数 + 对账 |
| 盘什么 | 全量扫，靠点位/货架位约束 | **只盘导入的那份清单** |
| 怎么分遍 | 点位 × 阶段 | **节点**：一趟一个节点，可开 3、4、5 趟 |
| 点位/货架位 | 必须有 | **完全不用**（现场不会为这个贴点位码） |
| 账面 | 看（`account_qty`）做盈亏 | **不看** |
| 出口 | 差异表 / 盈亏表 / 复核清单好几张 | **一个 CSV，三段** |
| 现状 | 0.16.0 已上线 | 本文档 |

🔴 **两者并存，不互相改。** 合成一个两边都不好用。

🔴 **最本质的缺口**：商档（`stock_master`）是**管理台**导入的，客户端根本没有
"导入本轮待盘清单"的能力 —— 现有流程里"要盘什么"是**全店一份**，
而简易通道里是**这一轮一份**（导一次、盘一轮、换一份）。这才是"背驰"的根。

⚠️ 顺带一条：**既然要独立，就真的独立**。不要去读 `stocktake_zone` /
`location` / `barcode_location` / `stock_master` 里任何一个 —— 一旦读了，
"盘点那边改了设置，简易盘点跟着变"这种问题就会冒出来，而且极难查。
商品名称从**导入的 CSV** 里来（CSV 里没有名称就留空）。

## 2. 流程

```
① 导入待盘清单        手机上选一个 CSV → 建一个「盘点任务」
   (1000 个商品)      任务号 SMP-20260925-120000，**场景选仓库 / 卖场**
        │
        ▼
② 第 1 趟：初盘       扫码，同码累加
        │
        ▼
③ 第 2 趟：复盘       扫码，同码累加。跟初盘比：
        │              数量一样 → **对上**（这个商品的数就定了）
        │              数量不一样 / 只有一边有 → **对不上** → 进差异集
        ▼
④ 第 3 趟：差异复盘   🔴 **只能扫差异集**（界面只列这些，扫别的直接拒）
        │              盘完 → **以差异复盘的数为最终数**
        ▼
⑤ 导出盘点数据单      一个 CSV，三段（见 §4）
```

**节点的 4 条规矩**：

1. **一趟一个节点**，按顺序编号（第 1 趟、第 2 趟…），类型 `初盘 / 复盘 / 差异复盘`。
2. 节点提交后本节点锁定（对齐现有单据的 `submit`），但**可以撤销**（对齐减货单）。
3. **同一场景同时只允许一个进行中的任务**（仓库一个、卖场一个，可以并存）。
   理由：同时开两个任务，员工根本不知道自己在盘哪一次。
4. **只有"第 3 趟"受差异集限制**。复盘**不**受限制 —— 复盘的价值就在于
   不知道哪里会错，先按差异集限制它，等于默认初盘是对的。

### 差异集怎么算（三个方向都要算，缺一个就漏商品）

用**本次任务自己的各趟**互比（不比账面），复刻现有 `InventoryRules` 的口径：

| 情况 | 算不算差异 |
|---|---|
| 初盘有、复盘有，数量不同 | ✅ 算 |
| 初盘有、复盘**没扫到** | ✅ 算（复盘漏盘） |
| 复盘有、初盘**没扫到** | ✅ 算（复盘新扫出来的，没有参照） |
| 初盘有、复盘有，数量相同 | ❌ 不算（对上了，差异复盘不再盘它） |

## 3. 数据模型

🔴 **只加 2 张表，其余复用** —— 复用不是省事，是避免漂移：
提交 / 撤销 / 导出 / 本地单号这四条链路现有代码已经写好、有测试钉着，
另起一套表等于把这四条各抄一遍，抄完两边就开始各修各的 bug。

```sql
-- 本地库 schemaVersion 3 → 4（按既有约定：只在 _migrations 末尾追加，不动已有函数）

-- ① 盘点任务（一轮）
CREATE TABLE simple_task (
  task_no    TEXT PRIMARY KEY,           -- SMP-20260925-120000
  task_name  TEXT,                       -- 「9月生鲜大盘」；空则用导入的文件名
  scene      TEXT NOT NULL DEFAULT 'store', -- 🔴 store 卖场(门店) / warehouse 仓库
  total_items INTEGER NOT NULL DEFAULT 0,
  status     INTEGER NOT NULL DEFAULT 0, -- 0进行中 1已归档
  created_at INTEGER,
  closed_at  INTEGER
);

-- ② 待盘清单（导入的明细）
CREATE TABLE simple_item (
  task_no  TEXT NOT NULL,
  barcode  TEXT NOT NULL,
  name     TEXT,
  spec     TEXT,
  seq      INTEGER,                      -- 导入顺序；导出照这个排，员工好对数
  PRIMARY KEY (task_no, barcode)
);
CREATE INDEX idx_simple_item_task ON simple_item(task_no, seq);
CREATE INDEX idx_simple_task_scene ON simple_task(scene, status);
```

**节点和明细都不新建表，直接复用现有两张**：

| 概念 | 落在哪 | 怎么区分 |
|---|---|---|
| 一个节点 | `stocktake_sheet` | `sheet_type='simple'`；`zone_code` 存**任务号**；`phase` = 1初盘 / 2复盘 / 3差异复盘 |
| 一笔扫码 | `scan_record` | `sheet_no` = 节点号（`SMP-20260925-120000-01`） |

🔴 `zone_code` 是借来存任务号的：简易通道**本来就不看点位**，这一列在这条通道里
没有别的含义。借它承载"这一趟属于哪个任务"，比新增一列（要动现有读表的所有地方）
和新建一套表（要抄四条链路）都划算。

🔴 **`phase` 的取值和「盘点」共用 1/2/3**，但**标签不同**：盘点是"初盘/复盘/抽盘"，
这里是"初盘/复盘/差异复盘"。含义也略不同：抽盘是主管抽查，差异复盘是补盘 + 核准。
标签由各自的界面给，**不要去改共用的 `InvPhase.label`**。

🔴 老版本 App 读到 `sheet_type='simple'` 的单：现有代码按 `sheet_type` 过滤，
认不出的类型既不进「盘点」也不进「减货」列表 —— **看不见，不会出错**。

## 4. 导出的三段（一个 CSV）

| 段 | 抬头 | 内容 | 数量列 |
|---|---|---|---|
| 1 | **盘点数据** | 已确定的商品（初盘复盘一致 / 差异复盘确认） | 最终数 |
| 2 | **未盘到商品** | 清单里有、但整个流程一个数都没有 | **0** |
| 3 | **未录入盘点计划商品** | 扫到了、但不在导入清单里 | 实盘数 |

每段三列，顺序照龙哥说的：**`商品条码, 商品盘点数量, 商品名称`**。

**排序**：按导入顺序（`seq`），**未盘到的不单独排最后** —— 他就是按单子一行行对数的。
第 3 段按条码排（它们没有导入顺序）。

**数量格式**：整数不带小数点，称重带小数（沿用 `fmtQty`）；未盘到的写 **0** 不是空。
**带 BOM**（Excel 双击不乱码）+ **长条码用 `="..."`**（防科学计数法）—— 都是现有导出件已解决的坑。

### 🔴 还有"对不上但还没做差异复盘"的商品怎么办

这是个**不能不处理**的情况：第 2 趟盘完、第 3 趟还没做，此时导出，这批商品
既不在段 1（数还没定）、也不该进段 2（它们**盘到了**，写 0 是错的）。

处理方式：

- 界面上**常显**一条「**N 个商品有差异待复核**」，点进去就是差异复盘的入口；
- 导出时若 N > 0，**先提示**："还有 N 个商品有差异没复核，现在导出会缺这 N 个。"
  给两个选择：**去做差异复盘**（推荐）／ **仍然导出**；
- 选择仍然导出时，这 N 个商品作为**第 4 段「差异待复核」**附在最后（数量列留空）。
  **绝不允许把它们悄悄丢掉** —— 数据丢了比格式不好看严重得多。

正常流程走完（差异复盘做完了），第 4 段自然为空，导出的就是干净的三段 ——
所以**不影响**龙哥说的"一个 CSV，三段"。

## 5. 界面

**入口**：工作台一张独立卡片「简易盘点」（`simple_stocktake`，图标 `list`），
**紧挨着「盘点」**。这是龙哥特意定的 —— 库房减货当初藏在盘点页图标里，他说"我没找到"。

**页面**（一页搞定，不搞多层）：

| 区域 | 内容 |
|---|---|
| 顶部 | 任务号 + 任务名 + **场景标（仓库/卖场）** + 「已盘 51 / 1000 个品」 |
| 当前节点 | 「第 2 趟 · 复盘」+ 「完成本趟」按钮 |
| 差异提示 | 有差异待复核时：**N 个商品有差异待复核** → 点进差异复盘 |
| 扫码区 | 扫码输入框（扫码枪 HID / 摄像头）+ 上一笔的数量可改 |
| 明细 | 本趟盘到的行（条码 / 名称 / **本趟数量**）；**空也画表头** |
| 底部栏 | 「历史趟次」·「导出盘点数据单」·「换一份清单」**常显** |

🔴 「导入清单」按钮**常显**：第一次进来没导入时，整页不能是一片空白 ——
直说"请先导入这一轮要盘的商品清单（CSV）"并给按钮、给模板下载。

🔴 第 3 趟（差异复盘）进门时：**只能扫差异集**，所以列表直接就是差异清单，
扫到不在差异集里的 → 明确拒绝（对齐现有 `notInDiffSet` 的文案口径）。

**CSV 导入格式**（容错优先，现场没人愿意改文件头）：

| 商品条码 | 商品名称 | 规格 |
|---|---|---|
| 6901234567890 | 农夫山泉 550ml | 550ml |

- 有表头：认「条码/商品条码/barcode」「名称/商品名称/name」「规格」，顺序随便
- 没表头：按**第 1 列条码、第 2 列名称**读
- 条码去空格、去 Excel 留下的 `="` 包裹；空行跳过；**同条码重复只留一行**
- 导入结果要报数：「导入 1000 条，跳过重复 3 条，跳过没条码 1 条」——
  不报数的话导错了没人知道

## 6. 分期

| 期 | 内容 | 出口 |
|---|---|---|
| **S1** | 导入清单 + 任务（含场景） + 单节点扫码 + 导出三段 | 真机：导 1000 条 → 盘 50 个 → 导出 1000 行，50 行有数、950 行 0 |
| **S2** | 多节点（复盘/差异复盘）+ 差异集计算 + 只扫差异 + 历史趟次 + 撤销提交 | 初盘 5 / 复盘 3 → 该商品**不在段 1**；差异复盘改成 5 → 段 1 出 5 |
| S3 | 任务归档清理 + 差异待复核第 4 段 | 对账用 |

**S1 就要能验收**：先把"导进去 → 盘 → 导出对账"这条直线打通，不堆功能。

## 7. 验收（真机，写完照这个走）

1. 用 Excel 造 1000 行 CSV（含 1 行重复条码、1 行空条码）→ 导进手机
   → 报数："1000 条 / 重复 1 / 空条码 1"（**数字要能对上**）
2. 盘 50 个品，其中 3 个扫两遍 → 那 3 个的数量是 2（**同一趟内累加**）
3. 加一个清单外的商品 → 有黄条提醒，且**入账**
4. 第 2 趟复盘：把某 1 个商品盘成**和初盘不同的数** → 界面上出现
   「1 个商品有差异待复核」，此时导出 → **该商品不在段 1**（不是 5、也不是 3）
5. 第 3 趟差异复盘：只能看到那 1 个商品（**对上的不出现**）；扫别的 → 被拒
   盘成 5 → 导出该商品 = **5**
6. 导出 CSV：段 1 有数的 + 段 2 写 0 的 + 段 3 清单外的；
   Excel 双击不乱码、长条码没变成 `6.9E+12`
7. 导出**整个 CSV 的行数** = 段1 + 段2 + 段3，且**段1 + 段2 = 导入清单的行数**
   （这条是防"悄悄少了几行"的硬判据）
8. 「换一份清单」→ 导入第 2 份 → 上一轮的数据**还在**（导出上一轮仍对）
9. 场景标识：建一个「仓库」任务 + 一个「卖场」任务，两个可以并存，
   导出互不串数

## 8. 待龙哥一句话确认

**「一趟内同码累加」这条我理解对没有**：同一条码在**同一趟里**扫两次
（比如货架上一份、仓库里一份），数量**相加**（1 + 1 = 2）；
而初盘与复盘之间的数字**不相加**，只用来判断"对没对上"。

# 简易盘点通道 方案 v1

> 龙哥 2026-09-25 提的：现在做的「盘点」是**制度型**（点位 / 货架位 / 三遍互比），
> 跟他在现场干活的方式背驰。他要的是**一条简易通道**：先导入这一轮要盘的明细，
> 再一趟一趟地盘（节点），最后导出一张全量盘点数据单。
>
> 三条口径已确认（2026-09-25）：
> 1. **同一商品被两次盘到 → 数量相加**（初盘 5 + 复盘 3 = 8）
> 2. 入口 = **单独一张工作台卡片**（不藏在别的页面里）
> 3. 待盘清单 = **手机上选 CSV 文件导入**（跟小智扫码枪导商档一样的做法）

---

## 0. 先说清"背驰"在哪 —— 别把两件事混在一起

| | 现有「盘点」（inventory） | 新的「简易盘点」（simple_stocktake） |
|---|---|---|
| 出发点 | **制度**：谁在哪个点位、第几遍、失误几笔 | **干活**：这一堆货我点数，点完给我一张单 |
| 盘什么 | 全量扫，靠点位/货架位约束 | 只盘**导入的那份清单** |
| 怎么分遍 | 点位 × 三阶段（初盘/复盘/抽盘），阶段间**互比差异** | **节点**：一趟就是一个节点，可以开 3、4、5 趟 |
| 数量怎么来 | 每阶段一个平行数量，差异 = 本阶段 − 上一阶段 | **所有节点相加**，一个商品最后只有**一个数** |
| 要不要点位 | 要（扫点位码开单） | **不要**（现场根本不会为这个贴点位码） |
| 看不看账面 | 看（`account_qty`）做盈亏 | **不看**（导出只有实盘数量） |
| 出口 | 差异表 / 盈亏表 / 复核清单（好几张表） | **一张盘点数据单**（三列，含没盘到的 0） |
| 现状 | 0.16.0 已上线 | 本文档 |

🔴 **两者并存，不互相改**。现有「盘点」一行不动 —— 它是给要审计的场景用的；
简易通道是给"今天要把这批货点清楚"用的。合成一个，两边都不好用。

🔴 **商档是管理台导的，客户端没有"导入本轮待盘清单"的能力** —— 这是最本质的缺口。
现有流程里，"要盘什么"这件事是**全店一份**（`stock_master`）；
而简易通道里，"要盘什么"是**这一轮一份**（导一次、盘一轮、换一份）。

---

## 1. 流程

```
① 导入待盘清单            手机上选一个 CSV → 建一个「盘点任务」
   (1000 个商品)          任务号 SMP-20260925-120000
        │
        ▼
② 开第一趟（节点① 初盘）   扫码 → 数量自动累加（同码再扫就是加一件）
        │                 扫到清单外的商品：**入账**，给黄条提醒（不拦）
        ▼
   「完成本趟」→ 开第二趟（节点② 复盘）→ …第 N 趟
        │
        ▼
③ 导出盘点数据单          全量 = 导入的清单
                          盘到的：条码 + 实盘数量 + 名称
                          没盘到的：条码 + 0 + 名称
        │
        ▼
④ 清干净再下一轮          任务归档，导入下一份 CSV
```

**节点的三条规矩**（都为了"现场好判断"）：

1. **一趟一个节点**，节点按顺序编号（第 1 趟、第 2 趟…），类型选
   `初盘 / 复盘 / 差异复盘`（只是**标记**，不影响累计口径）。
2. **累计不在扫码时算，在导出时统一算** —— 这样撤销/改单都不会算错，
   也不存在"以为算过了"的中间状态。
3. 「完成本趟」后本节点锁定（对齐现有单据的 `submit`），
   但**可以撤销**（对齐减货单的撤销提交）。

## 2. 数据模型

🔴 **只加 2 张表，其余全部复用** —— 复用不是省事，是避免漂移：
提交 / 撤销 / 导出 / 本地单号这四条链路现有代码已经写好、有测试钉着，
另起一套表等于把这四条各抄一遍，抄完两边就开始各修各的 bug。

```sql
-- 本地库 schemaVersion 3 → 4（按既有约定：只在 _migrations 末尾追加，不动已有函数）

-- ① 盘点任务（一轮）
CREATE TABLE simple_task (
  task_no    TEXT PRIMARY KEY,          -- SMP-20260925-120000
  task_name  TEXT,                      -- 「9月生鲜大盘」；空则用导入的文件名
  total_items INTEGER NOT NULL DEFAULT 0,
  status     INTEGER NOT NULL DEFAULT 0, -- 0进行中 1已归档
  created_at INTEGER,
  closed_at  INTEGER
);

-- ② 待盘清单（导入的明细）
CREATE TABLE simple_item (
  task_no  TEXT NOT NULL,
  barcode  TEXT NOT NULL,
  name     TEXT,
  spec     TEXT,
  seq      INTEGER,                     -- 导入顺序；导出照这个排，员工好对数
  PRIMARY KEY (task_no, barcode)
);
CREATE INDEX idx_simple_item_task ON simple_item(task_no, seq);
```

**节点和明细都不新建表，直接复用现有两张**：

| 概念 | 落在哪 | 怎么区分 |
|---|---|---|
| 一个节点 | `stocktake_sheet` | `sheet_type='simple'`；`zone_code` 存**任务号**；`phase` = 1初盘 / 2复盘 / 3差异复盘 |
| 一笔扫码 | `scan_record` | `sheet_no` = 节点号（`SMP-...-01`） |

🔴 `zone_code` 借来存任务号：简易通道**本来就不看点位**，这一列在这条通道里没有别的含义，
借它承载"这一趟属于哪个任务"，累计就是一句 SQL（见 §3）。
**不比新建 `task_no` 列好，但比新建一套表好得多** —— 新增一列要动现有读表的所有地方。

🔴 老版本 App 读到 `sheet_type='simple'` 的单会怎么办：现有代码按 `sheet_type` 过滤，
认不出的类型不进「盘点」也不进「减货」列表 —— **看不见，不会出错**。
和 `deduct` 当初的做法一致。

## 3. 累计与导出（核心口径）

**累计 = 该任务下所有节点的数量相加**，一条 SQL：

```sql
SELECT r.barcode, SUM(r.qty) AS qty
FROM scan_record r
JOIN stocktake_sheet s ON s.sheet_no = r.sheet_no
WHERE s.sheet_type = 'simple' AND s.zone_code = :task_no
GROUP BY r.barcode
```

**导出 = 待盘清单 LEFT JOIN 上面的累计结果**（这才是"没盘到的也出 0 行"的写法：

```
LEFT JOIN 的方向决定了"以清单为准"。反过来写（从 scan_record 出发）
就只能导出盘到的那些 —— 而"盘点结束没盘到的商品明细"正是他要的。
```

**导出的 CSV**（三列，顺序照龙哥说的）：

| 商品条码 | 商品盘点数量 | 商品名称 |
|---|---|---|
| 6901234567890 | 8 | 农夫山泉 550ml |
| 6901234567891 | 12.5 | 散装花生（称重） |
| 6901234567892 | 0 | 康师傅红烧牛肉面 |

- **第一列数字、第二列数量、第三列名称**（`商品条码+商品盘点数量+商品名称`，按他给的顺序）
- 数量：整数不带小数点，称重带小数（沿用 `fmtQty`）
- 未盘到的写 **0**，不是空
- 排序：按导入顺序（`seq`），**未盘到的不单独排最后** —— 他就是按单子一行行数的
- 带 BOM（Excel 双击不乱码）+ 长条码用 `="..."`（防科学计数法）—— 都是现有导出件已解决的坑

**扫到清单外的商品**：入账（**不拦**，现场扫到就是有货），导出时**一并列出**并排在清单商品之后。
理由：拦掉会让人"扫了没反应"，以为机器坏了；而悄悄丢掉会让实数少了。
名称从商档补，补不到就留空 —— 界面会给黄条「不在待盘清单内」，让人当场知道。

## 4. 界面

**入口**：工作台一张独立卡片「简易盘点」（`simple_stocktake`，图标 `list_alt`），
排在「盘点」后面。**这是龙哥特意定的** —— 库房减货当初藏在盘点页图标里，他找不到。

**页面**（一页搞定，不搞多层）：

| 区域 | 内容 |
|---|---|
| 顶部 | 当前任务号 + 任务名 + 「已盘 51 / 1000 个品」 |
| 当前节点 | 「第 2 趟 · 复盘」+ 「完成本趟」按钮 |
| 扫码区 | 扫码输入框（扫码枪 HID / 摄像头）+ 上一笔的数量可改 |
| 明细 | 本趟盘到的行（条码 / 名称 / 本趟数量）；**空也画表头** |
| 底部栏 | 「历史趟次」·「导出盘点数据单」·「换一份清单」**常显** |

🔴 「导入清单」按钮**常显**：第一次进来没导入时，整页不能是一片空白 ——
直说"请先导入这一轮要盘的商品清单（CSV）"并给按钮。

**CSV 导入格式**（容错优先，现场没人愿意改文件头）：

| 商品条码 | 商品名称 | 规格 |
|---|---|---|
| 6901234567890 | 农夫山泉 550ml | 550ml |

- 有表头：认「条码/商品条码/barcode」「名称/商品名称/name」「规格」，顺序随便
- 没表头：按**第 1 列条码、第 2 列名称**读
- 条码去空格、去 Excel 留下的 `="` 包裹；空行跳过；**同条码重复只留一行**
- 导入结果要报数：「导入 1000 条，跳过重复 3 条，跳过没条码 1 条」——
  不报数的话导错了没人知道

## 5. 分期

| 期 | 内容 | 出口 |
|---|---|---|
| **S1** | 导入清单 + 任务 + 单节点扫码 + 累计 + 导出 | 真机：导 1000 条 → 盘 50 个 → 导出 1000 行，50 行有数、950 行 0 |
| **S2** | 多节点（开第 2/3 趟）+ 历史趟次 + 撤销提交 | 一个商品跨两趟盘到，导出是两趟之和 |
| S3 | 节点级明细导出 + 任务归档清理 | 对账用 |

**S1 就要能验收**：不堆功能，先把"导进去 → 盘 → 导出对账"这条直线打通。

---

## 6. 验收（真机，写完照这个走）

1. 用 Excel 造一份 1000 行的 CSV（含 1 行重复条码、1 行空条码）→ 导进手机
   → 提示"1000 条 / 重复 1 / 空条码 1"（数字要能对上）
2. 盘 50 个品，其中 3 个扫两遍 → 那 3 个的数量是 2（**同节点内累加**）
3. 加一个清单外的商品 → 有黄条提醒，且**入账**
4. 「完成本趟」→ 开第 2 趟 → 把第 2 步里的某 1 个再盘一次（数量 5）
   → 导出该行 = 2 + 5 = **7**（跨节点相加）
5. 导出 CSV：**1000 行**（+1 行清单外），没盘到的数量是 **0** 不是空；
   Excel 双击打开不乱码、长条码没变成 `6.9E+12`
6. 「换一份清单」→ 导入第 2 份 → 上一轮的数据**还在**（导出上一轮仍对）

## 7. 待龙哥确认的 2 处（不影响开工，边做边说）

1. **「差异复盘」这一趟要不要限制只能扫有差异的？**
   现在的设想是**不限制**（只是个名字/标记），因为"差异"在简易通道里没有基准可比 ——
   不比账面、也不跟前一趟比。如果他要的是"第 3 趟只显示前两趟对不上的那些"，
   那是另一种做法（要在节点间做比较），得先说定。
2. **一个任务同时只有一趟，还是要能多趟并行？**
   现在设想**一趟一趟来**（同时只有一张进行中的节点单），简单、不容易乱。
   如果现场是几个人各盘一片、各自开趟，那就要支持并行 + 按人区分。
